Lesson 5: Gaps & Improvement Opportunities

What's missing, and how to make each tool better

Framework for Gap Analysis

Evaluate systematically across these dimensions:

  1. Workflow completeness — Does it cover the full cycle?
  2. Brownfield support — How well does it handle existing code?
  3. Team collaboration — Multi-person, multi-repo scenarios?
  4. Customization — Can you adapt it to your process?
  5. Verification — How do you know the spec was followed?

OpenSpec Gaps

GapImpactPotential Fix
No constitution Project-wide standards communicated separately Add /opsx:constitution
No extension system Can't add custom commands Plugin architecture
No reconciliation Can't verify spec vs implementation Add /opsx:verify
Stores are beta Cross-repo not production-ready Stabilize stores
Key OpenSpec Improvement A /opsx:verify command checking if implementation matches spec would address spec drift.

SpecKit Gaps

GapImpactPotential Fix
No explore phase Must commit to structured spec immediately Add /speckit.explore
No archive state Completed specs clutter workspace Add /speckit.archive
Weak brownfield No delta markers Add ADDED/MODIFIED/REMOVED
More ceremony 4+ commands for simple changes Add /speckit.quick
No cross-repo Multi-service needs manual coordination Add stores-like feature
Key SpecKit Improvement A /speckit.quick combining specify→plan→tasks would reduce ceremony for small features.
