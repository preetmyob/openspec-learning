Lesson 4: Head-to-Head Comparison

OpenSpec vs SpecKit across every dimension

Philosophy Comparison

OpenSpec

  • Fluid, iterative
  • Brownfield-first
  • Single-command artifact creation
  • Explore before commit

SpecKit

  • Structured, phased
  • Greenfield-optimized
  • Multi-command refinement
  • Constitution-first

Feature-by-Feature

FeatureOpenSpecSpecKit
Project principles ❌ None ✅ Constitution
Discovery phase ✅ /opsx:explore (conversational) ⚠️ /speckit.clarify (structured)
Artifact creation Single command Multiple commands
Brownfield support ✅ Delta markers ⚠️ Basic
Completion state ✅ /opsx:archive ❌ Manual
Reconciliation ❌ None ✅ /speckit.converge
Extension system ⚠️ Schemas only ✅ Extensions/presets/bundles
Cross-repo planning ✅ Stores (beta) ❌ None
Installation npm (Node.js) uv/pip (Python)

When to Choose Each

ScenarioBetter ChoiceWhy
Brownfield changes OpenSpec Delta markers reduce spec size
Greenfield project SpecKit Constitution + structured phases
Quick iteration OpenSpec Less ceremony
Enterprise compliance SpecKit Presets for templates
Cross-repo features OpenSpec Stores feature (beta)
Deep customization SpecKit Extension ecosystem
