# Mission: Evaluate OpenSpec vs SpecKit for Spec-Driven Development

## Why I'm Learning This

I need to evaluate OpenSpec and SpecKit to understand which tool (or combination) best serves my team's spec-driven development workflow. The goal is not just tool selection — it's identifying gaps and improvement opportunities in either tool.

## Context

- **Team size**: Team environment (not solo)
- **Project type**: Both greenfield and brownfield codebases
- **AI assistants**: Cursor and Claude Code
- **Evaluation scope**: Deep understanding of both tools' philosophies, workflows, and limitations

## Success Criteria

By the end of this learning journey, I should be able to:

1. **Explain** the core philosophy and workflow of both OpenSpec and SpecKit
2. **Compare** their approaches to spec lifecycle, artifacts, and agent integration
3. **Identify** specific gaps or limitations in each tool
4. **Propose** concrete improvements that would address those gaps
5. **Recommend** which tool (or hybrid approach) fits specific use cases

## Key Questions to Answer

- What problem does each tool solve, and how do their approaches differ?
- Where does each tool excel vs struggle?
- What's missing that would make either tool significantly better?
- Could the best ideas from both be combined?

## Constraints

- Focus on practical evaluation, not just theoretical understanding
- Ground analysis in real-world team workflows with Cursor and Claude Code
- Prioritize actionable insights over comprehensive documentation
